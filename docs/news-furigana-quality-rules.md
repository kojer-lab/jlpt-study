# 일본 뉴스 후리가나 품질 관리 규칙

> 적용 대상: KOJER JLPT STUDY의 날짜별 뉴스 기사 전체(N1/N2 포함).  
> 기준일: 2026-10-18. 이 문서는 앞으로의 기사 작성·수정·배포 시 필수 체크리스트다.

## 2026-10-18 수정 작업에서 얻은 교훈

2026-10-18 기사 6개에서 후리가나 누락이 보고되었다. 이후 누락 후리가나 및 숫자·날짜 읽기 보완, 한자 후리가나 누락 검사 강화, iPhone Safari 캐시 버전 갱신이 적용되었다는 작업 보고가 있었다.

이 문서는 그 **재발 방지 요구사항**을 명문화한다. 개별 수정 원인의 상세한 기술적 결론은 실제 커밋·검사 로그를 통해서만 확정한다.

## 앞으로 절대 생략하지 않을 원칙

1. 기사 생성 완료는 검수 완료가 아니다. **날짜별 JSON에 실제 저장된 본문·제목·문제·해설·보기**를 대상으로 검수한다.
2. 독자가 읽어야 하는 모든 일본어 한자 표기에 후리가나가 정확히 연결됐는지 검사한다. 표기상 한자가 하나라도 누락되면 **검수 실패**로 처리한다.
3. 한자 단어의 부분 누락, 복합어, 고유명사, 인명·지명, 조수사, 숫자·날짜·시간·단위의 문맥에 맞는 읽기를 별도 확인한다.
4. 숫자는 일반 기사에서 아라비아 숫자를 기본으로 사용한다. 단, 고유명사·관용구 등에 포함된 한자는 억지로 변환하지 않는다. 숫자 표기와 후리가나 읽기는 서로 모순되지 않아야 한다.
5. 한자 누락 탐지만으로 정확성을 보장할 수 없다. **후리가나의 잘못된 읽기, 경계, 불필요한 중복, 화면 렌더링 문제도 검수**한다.
6. 누락을 발견해 수정했다면 특정 문장만이 아니라 **같은 날짜의 기사 6개 전부를 재검수**한다. 수정 결과뿐 아니라 무엇이 누락을 일으켰는지 및 방지 규칙도 기록한다.
7. 발행 전 자동 검사에서 누락이나 스키마 오류가 검출되면 **커밋/배포를 통과시키지 않는다**. 자동 검사가 통과해도 주요 문단에 대한 눈검수는 수행한다.
8. 사이트는 날짜별 인덱스(`data/news-index-v1.js`)에서 해당 날짜의 `data/news-articles-YYYY-MM-DD.json`을 로드한다. **실제 로드되는 파일을 수정**하고 과거 백업용 `news-generated-*.js`, `news-curated-v1.js`만 수정하여 완료로 간주하지 않는다.
9. 데이터 변경 시 **인덱스 메타데이터·캐시 버전**을 확인한다. iPhone Safari에서 이전 파일이 계속 보이는 현상을 방지하고 실제 배포된 기사로 다시 확인한다.
10. GitHub Actions / Pages 배포가 실패했다면 **작업 완료로 보고하지 않는다**. 검증과 배포 성공 여부를 별개로 확인한다.

## 매번 뉴스 제작 시 필수 순서

- [ ] 6개 기사의 원문 출처·사실관계·발행 날짜 확인
- [ ] 날짜별 JSON 생성, 인덱스 연결 및 스키마 확인
- [ ] 제목·본문·문제·보기·해설에서 한자 후리가나 누락 자동 검사
- [ ] 인명·지명·숫자·날짜·조수사 읽기 및 한자/후리가나 대응 직접 확인
- [ ] 숫자 기본 표기가 아라비아 숫자인지 확인
- [ ] iPhone Safari의 실제 후리가나 표시·토글·캐시 재검증
- [ ] CI 검사 통과, GitHub Pages 배포 성공 확인
- [ ] 발견된 누락 사례·원인·수정 내용·재발 방지 방법을 Markdown 문서에 반영

## 실패 시 대응

후리가나 누락 발생 → 해당 날짜 6개 전수 재검사 → 실제 데이터 수정 → 누락 검사 재실행 → 숫자·읽기 수동 확인 → 인덱스/캐시 갱신 → CI/배포 확인 → 원인 및 예방책 문서화.

**최종 원칙: “후리가나가 하나라도 누락된 뉴스는 완료가 아니다.”**
