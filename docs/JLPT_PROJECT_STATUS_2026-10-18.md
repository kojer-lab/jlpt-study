## 2. 앱 구성과 개발 원칙

- 저장소의 메인 페이지는 `index.html`. N1/N2 단어 데이터는 `data/` 아래에 분할 저장.
- N1 어휘, N2 어휘, 예문, 안키 FSRS, 오답/별표, 문법·독해·청해, 모의고사, 시사독해, 별도의 '뉴스 읽기' 기능이 있다.
- 모바일 핵심 타깃은 **iPhone Safari**. PC에서 코드가 통과하더라도 iPhone에서 터치 반응 및 음성 재생을 별도 확인해야 한다.
- 공부 기록과 설정은 로컬 스토리지 기반, 로그인 시 Supabase 동기화 지원. 기존 SRS 기록을 보존하는 수정이 원칙.
- `후리가나 없음`은 **발음 문제가 아니라 표기/렌더링 문제**로 취급해 별도 유형으로 접수.
- 실전 학습 콘텐츠에는 일본어 지문, 한국어 번역, 답과 해설, 오답 보기 번역 등 최근 UI 규칙을 유지.

## 3. 최근 완료한 작업 (2026-10-14~18)

### A. 오늘의 시사독해 10/18~10/24 공개분

- **공개 날짜:** 2026-10-18(일)~10-24(토), 하루 3기사 × 3문제 = **21기사, 63문제**.
- 기존 **10/08~10/14** 공개분 21기사·63문제 유지. 전체 **42기사·126문제**.
- 신규 기사들의 참고 보도 날짜는 **10/13~10/16**. 최초 기획안의 주제 중 검증 근거가 약한 것은 다른 기사로 교체.
- 신규 문제마다 **한국어 문제 번역 + 오답 선택지 3개 번역**을 넣음(총 189개 오답 번역). 기사 지문은 일본어/한국어 2문단 대응.
- 실제 뉴스 기반의 **JLPT 학습용 재작성**임. 원문 기사 전문 재현이 아님. 기사 객체에 `sourceDate`, `source`, `sourceUrl` 기록.
- 공개 날짜 목록: **10/08, 09, 10, 11, 12, 13, 14 / 10/18, 19, 20, 21, 22, 23, 24**. 따라서 **10/15~10/17은 공개 데이터가 없는 기간**.
- 날짜별 콘텐츠는 데이터를 미리 작성한 뒤 날짜 기준으로 노출. 자동 기사 수집·AI 문제 제작·GitHub 업로드 시스템은 없음. 다음 주차는 별도 요청 및 제작 필요.
- 데이터: `data/n1-daily-news.js`. 앱 참조: `data/n1-daily-news.js?v=20261017-week2`.
- 수정 중 후리가나 생성 CI가 JSON 파싱에 실패한 적이 있음. 원인: 원래 배열 뒤에 `window.N1_DAILY_NEWS.push(...)`를 붙여 JSON 추출기가 인식 못함. **42기사 전체를 단일 `window.N1_DAILY_NEWS=[...];` 배열**로 정규화하여 해결.
- **GitHub Actions 후리가나 생성 재실행 성공** (단, 실제 iPhone 시사독해 화면은 별도 확인 필요).

### B. 안키 새 단어 등장 시 전체 화면이 멈추는 문제

- 기존에는 새 카드 표시 직후 `prefetchWordAudio()`가 MP3 누락 단어/예문에 대해 **iPhone Kokoro WASM 음성 합성**을 백그라운드처럼 시작.
- 해당 추론이 Safari 메인 스레드를 점유하면 페이지 전체 터치/클릭이 먹히지 않는 현상이 발생할 수 있음.
- **iOS 자동 합성 중단**, 준비된 정적 MP3 미리 읽기는 유지. 단어 목록에서 예문을 펼칠 때의 iOS 자동 합성도 방지.
- 스피커를 직접 눌러 MP3가 없는 음성을 생성하는 기능은 유지하므로, **수동 음성 생성 시 지연 가능성은 남음**.
- 이전 렌더링 최적화에서는 단어 카드 전환 때 상세 예문/단어 해부를 미리 만들지 않고 `뜻 · 예문 보기`를 누를 때 생성하도록 변경했음.
- **남은 확인:** iPhone Safari에서 스피커를 누르지 않고 새 단어 여러 장을 넘길 때 다른 화면 버튼까지 즉시 반응하는지. 앱 전체 프리징이 재현되면 CPU 작업과 동기화 등 추가 분석 필요.

### C. N2 안키 예문 후리가나 누락 보완

- 원인: `tools/export-word-furigana.mjs`가 기존에 N1만 수집해 N2 예문은 제한된 브라우저 자동 추정에 의존함.
- `data/n2-words-phase1.js` ~ `data/n2-words-phase32.js` **32개 파일 / 2,000개 N2 카드 예문**을 후리가나 생성 입력에 포함.
- GitHub Actions 실행 로그: **5,233개 단어, 예문 8,366개, 연관어 6,847개 처리**, 잔여 미표기 한자 자동 검사 통과.
- 생성물: `data/n1-word-furigana.js` (이름은 N1이지만 현재 N2 생성 예문도 포함).
- 캐시: `data/n1-word-furigana.js?v=20261018-n2-complete1`.
- **주의:** 형태소 분석 기반 생성 결과이므로 문맥상의 읽기 오류가 없다는 뜻은 아니다. N2 실제 iPhone 표시 및 발음은 별도 검증 필요.

### D. 예문 후리가나 신고 #72, #73 해결

- Supabase 신고: `n1x172` / `ひときわ`의 예문에서 후리가나가 보이지 않는 문제.
- 원인: 예문 순서/내용이 생성된 후리가나 배열과 달라 **인덱스만으로 매칭할 때 실패**하는 경우.
- `renderExampleJP()`가 **일본어 문장 내용을 기준으로 생성 후리가나를 검색**하도록 변경. 특정 누락 문장 `彼女の声は人混みの中でもひときわ目立った。`는 검증된 읽기 직접 보완.
- 두 신고는 당시 Supabase에서 `fixed`로 처리. 이후 전체 신고 기록 초기화 요청으로 레코드 자체는 삭제됨.

### E. 신고 UI와 신고 보관함 정리

- 신고 모달 제목을 **'발음·후리가나 오류 신고'**로 변경.
- `오류 유형` 선택지에 **'후리가나 없음'** 추가. 설명란 라벨/placeholder도 후리가나 신고에 맞게 개선.
- Supabase `jlpt_pronunciation_reports.error_type` CHECK 제약에도 동일한 새 유형 추가, DB 마이그레이션 성공.
- DB 정의 문서 `supabase_pronunciation_reports.sql`도 신규 설치·기존 설치용으로 갱신.
- 사용자의 초기화 요청에 따라 기존 오류 신고 **66건 삭제**, 직후 0건 확인. GitHub Issues 삭제와 다른 작업.
- **새로 접수된 미해결 신고 1건:** ID **74**, 단어 **摘む**, 카드 ID `oj-691f993a5a`, **예문 1**, 유형 `후리가나 없음`, 상태 `open`. 문서 작성 시점에는 **아직 수정하지 않음**.
- **주의:** DB 기록을 초기화했다고 새로운 신고가 자동으로 막히는 것이 아님. 현재 신고 1건은 새로 들어온 정상적인 신고다.

### F. GitHub 이슈 정리

- **#5 'Anki: 단기 카드 반복과 FSRS 시간 복습 분리'** — 사용자 요청에 따라 Closed/Completed로 처리.
- **#6 '발음 오류 · 滞る'** — 과거에 Closed/Completed 처리.
- **열린 GitHub 이슈는 0건**. 영구 삭제는 하지 않음.
- **핵심 구분:** #5를 닫았다는 것이 카드 수 기준 빠른 재등장 기능을 구현했다는 의미는 아님. 현재 코드의 `promoteQuickWord()`는 **비활성화**되어 있고, 정식 FSRS 시간 복습을 사용한다. 추후 변경 요청 시 이 부분 다시 설계.

- 사용자 요청 없이 기존 오류 신고를 일괄 삭제하지 않는다. 신고 수정 → 검증 → `fixed` 기록을 기본으로 한다.
- GitHub Issue는 별도 개발 과제이며, 신고 DB와 동일하지 않다.
- 데이터 생성 스크립트가 단일 JSON 할당 형식을 읽는지 확인하여 GitHub Actions 파싱 오류 재발을 방지한다.
- 기능 반영 시 **코드 수정 → 데이터/구문 검사 → GitHub Actions → iPhone Safari 실사용 검증** 순서를 구분해 결과를 보고한다.
- 후리가나 생성 결과가 있어도 카드 원문과 일치하지 않으면 표시되지 않을 수 있다. `renderExampleJP()`의 **문장 내용 기반 매칭**을 유지한다.
- iPhone 카드 전환 시 자동 Kokoro WASM 추론을 재활성화하지 않는다. MP3 우선·터치 반응 유지가 더 중요하다.
